\section{Project Scope}

\subsection{In Scope}

The SkillChain platform encompasses the following features and capabilities:

\begin{itemize}
    \item User registration and profile management for both clients and freelancers.
    \item Job posting with detailed descriptions, budgets, and requirements.
    \item Proposal submission and management system.
    \item Smart contract-based escrow for secure payment holding.
    \item Mutual approval mechanism for job completion and payment release.
    \item IPFS integration for decentralized data storage.
    \item Web3 wallet integration for blockchain interactions.
    \item Real-time job and proposal tracking dashboard.
    \item Role-based access control (Client vs. Freelancer).
\end{itemize}

\subsection{Out of Scope}

The following features are not included in the current implementation but are planned for future releases:

\begin{itemize}
    \item Decentralized dispute resolution with third-party arbitration.
    \item On-chain reputation and rating system.
    \item Multi-token support (ERC-20 tokens).
    \item Layer 2 scaling solutions (Arbitrum, Optimism).
    \item Push notifications and real-time messaging.
    \item Milestone-based payment schedules.
    \item Time tracking integration.
\end{itemize}

\section{User Classes and Characteristics}

\subsection{Clients}

\begin{itemize}
    \item \textbf{Description:} Users who post jobs and hire freelancers.
    \item \textbf{Technical Expertise:} Basic understanding of cryptocurrency wallets.
    \item \textbf{Frequency of Use:} Occasional to frequent job posting.
    \item \textbf{Security Level:} High - handles ETH for escrow deposits.
\end{itemize}

\subsection{Freelancers}

\begin{itemize}
    \item \textbf{Description:} Users who submit proposals and complete work.
    \item \textbf{Technical Expertise:} Basic understanding of cryptocurrency wallets.
    \item \textbf{Frequency of Use:} Regular proposal submissions and work delivery.
    \item \textbf{Security Level:} Medium - receives payments but does not deposit.
\end{itemize}

\section{Assumptions and Dependencies}

\subsection{Assumptions}

\begin{enumerate}
    \item Users have access to modern web browsers with Web3 capabilities.
    \item Users possess or can create cryptocurrency wallets (MetaMask, Rainbow, etc.).
    \item Users have basic understanding of blockchain transactions and gas fees.
    \item Ethereum network is available and operational.
    \item IPFS network is accessible for content retrieval.
    \item Users have stable internet connectivity.
\end{enumerate}

\subsection{Dependencies}

\begin{enumerate}
    \item Ethereum blockchain network (local, testnet, or mainnet).
    \item IPFS/Pinata service for decentralized storage.
    \item Wallet providers (MetaMask, Rainbow, etc.).
    \item Web3 libraries (wagmi, viem, RainbowKit).
    \item Node.js runtime environment.
    \item Modern web browsers supporting ES6+ JavaScript.
\end{enumerate}

\section{Functional Requirements}

\subsection{User Profile Management}

\begin{itemize}
    \item \textbf{FR-1.1:} System shall allow users to create profiles with username, role, and metadata.
    \item \textbf{FR-1.2:} System shall enforce unique usernames across all users.
    \item \textbf{FR-1.3:} System shall support two roles: Client and Freelancer.
    \item \textbf{FR-1.4:} System shall store profile data on IPFS and reference via CID.
    \item \textbf{FR-1.5:} System shall allow profile updates while maintaining username uniqueness.
\end{itemize}

\subsection{Job Management}

\begin{itemize}
    \item \textbf{FR-2.1:} System shall allow clients to create jobs with title, description, budget, and metadata.
    \item \textbf{FR-2.2:} System shall require ETH deposit equal to job budget during creation.
    \item \textbf{FR-2.3:} System shall lock deposited funds in smart contract escrow.
    \item \textbf{FR-2.4:} System shall allow clients to view their posted jobs.
    \item \textbf{FR-2.5:} System shall allow freelancers to browse available jobs.
    \item \textbf{FR-2.6:} System shall track job status (Open, In Progress, Completed).
\end{itemize}

\subsection{Proposal Management}

\begin{itemize}
    \item \textbf{FR-3.1:} System shall allow freelancers to submit proposals for open jobs.
    \item \textbf{FR-3.2:} System shall store proposal details on IPFS.
    \item \textbf{FR-3.3:} System shall allow clients to view proposals for their jobs.
    \item \textbf{FR-3.4:} System shall allow clients to approve proposals.
    \item \textbf{FR-3.5:} System shall automatically hire freelancer upon proposal approval.
    \item \textbf{FR-3.6:} System shall prevent multiple proposals from same freelancer for same job.
\end{itemize}

\subsection{Payment and Escrow}

\begin{itemize}
    \item \textbf{FR-4.1:} System shall hold client funds in escrow upon job creation.
    \item \textbf{FR-4.2:} System shall allow freelancer to mark job as completed with deliverables.
    \item \textbf{FR-4.3:} System shall allow client to mark job as completed.
    \item \textbf{FR-4.4:} System shall release funds only upon mutual approval from both parties.
    \item \textbf{FR-4.5:} System shall transfer funds directly to freelancer's wallet upon release.
    \item \textbf{FR-4.6:} System shall prevent fund release before both parties approve.
\end{itemize}

\section{System Requirements}

\subsection{Database Requirements}

The system uses IPFS for decentralized storage with the following data structures:

\begin{itemize}
    \item Profile metadata stored as JSON objects.
    \item Job details stored as JSON objects with IPFS CIDs.
    \item Proposal details stored as JSON objects.
    \item Deliverables stored as files or JSON objects.
    \item Blockchain stores only references (CIDs) and critical state.
\end{itemize}

\section{Analysis Models}

\subsection{Data Flow}

The system follows a multi-layer data flow:

\begin{enumerate}
    \item User interacts with frontend interface.
    \item Frontend communicates with smart contracts via Web3.
    \item Smart contracts interact with blockchain state.
    \item Frontend reads/writes metadata to IPFS.
    \item Blockchain events trigger UI updates.
\end{enumerate}

\subsection{System Implementation Plan}

\begin{enumerate}
    \item \textbf{Phase 1:} Smart contract development and testing.
    \item \textbf{Phase 2:} Frontend development and Web3 integration.
    \item \textbf{Phase 3:} IPFS integration and content management.
    \item \textbf{Phase 4:} Testing and security audit.
    \item \textbf{Phase 5:} Deployment and documentation.
\end{enumerate}
