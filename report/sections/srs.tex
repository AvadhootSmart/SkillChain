\section{Project Scope}

\subsection{In Scope}

The SkillChain platform encompasses the following features and capabilities:

\begin{itemize}
    \item User registration and profile management for both clients and freelancers.
    \item Job posting with detailed descriptions, budgets, and requirements.
    \item Proposal submission and management system.
    \item Smart contract-based escrow for secure payment holding.
    \item Mutual approval mechanism for job completion and payment release.
    \item IPFS integration for decentralized data storage.
    \item Web3 wallet integration for blockchain interactions.
    \item Real-time job and proposal tracking dashboard.
    \item Role-based access control (Client vs. Freelancer).
\end{itemize}

\subsection{Out of Scope}

The following features are not included in the current implementation but are planned for future releases:

\begin{itemize}
    \item Decentralized dispute resolution with third-party arbitration.
    \item On-chain reputation and rating system.
    \item Multi-token support (ERC-20 tokens).
    \item Layer 2 scaling solutions (Arbitrum, Optimism).
    \item Push notifications and real-time messaging.
    \item Milestone-based payment schedules.
    \item Time tracking integration.
\end{itemize}

\section{User Classes and Characteristics}

\subsection{Clients}

Users who post jobs and hire freelancers. They require a basic understanding of cryptocurrency wallets, use the platform occasionally to frequently for job posting, and operate at a high security level because they handle ETH for escrow deposits.

\subsection{Freelancers}

Users who submit proposals and complete work. They require a basic understanding of cryptocurrency wallets, use the platform regularly for proposal submissions and work delivery, and operate at a medium security level (they receive payments but do not deposit).

\section{Functional Requirements}

\subsection{User Profile Management}

The system shall allow users to create profiles with unique usernames and role selection (Client or Freelancer). Profile data is stored on IPFS and referenced via CID, with uniqueness enforcement and update capabilities (FR-1.1 to FR-1.5).

\subsection{Job Management}

Clients can create jobs with title, description, and budget, requiring ETH deposit equal to the budget amount. Funds are locked in escrow, with job status tracking through Open, In Progress, and Completed states (FR-2.1 to FR-2.6).

\subsection{Proposal Management}

Freelancers submit proposals for open jobs with details stored on IPFS. Clients can view and approve proposals, which automatically hires the freelancer. The system prevents duplicate proposals from the same freelancer for one job (FR-3.1 to FR-3.6).

\subsection{Payment and Escrow}

The escrow system holds client funds upon job creation. Both freelancer and client must mark the job complete for fund release, which transfers ETH directly to the freelancer's wallet. The system prevents premature fund release (FR-4.1 to FR-4.6).

\section{System Requirements}

\subsection{Database Requirements}

The system uses IPFS for decentralized storage with the following data structures:

\begin{itemize}
    \item Profile metadata stored as JSON objects.
    \item Job details stored as JSON objects with IPFS CIDs.
    \item Proposal details stored as JSON objects.
    \item Deliverables stored as files or JSON objects.
    \item Blockchain stores only references (CIDs) and critical state.
\end{itemize}

\section{Analysis Models}

\subsection{Data Flow}

The system follows a multi-layer data flow:

\begin{enumerate}
    \item User interacts with frontend interface.
    \item Frontend communicates with smart contracts via Web3.
    \item Smart contracts interact with blockchain state.
    \item Frontend reads/writes metadata to IPFS.
    \item Blockchain events trigger UI updates.
\end{enumerate}
